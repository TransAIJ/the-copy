# THE・COPY

他人のコンテンツを1本まるごと写すのではなく、**それが売れている理由を部品ごとに見つけて写し、自分の型にする**ための手順です。
できた型は、次から同じ種類の物を何本でも同じ質で作るための自分のスキルとして残ります。

| | 中身 | 扱い |
|---|---|---|
| ①写す物 | 売れている理由、構造（話の順番・区画の順・見せ方）、中身（扱っている話題と論点）、情報量（項目・事例・手順の数） | 写します |
| 写さない物 | 寸法（文字の px・余白・字の大きさ・1文の字数）と言い回し | 写しません。寸法は自分のブランドの決まりと読みやすさで決め、言葉は自分の言葉で書きます |
| ②一次情報 | 実績・数字・体験・写真・声・商品 | 写さずに、自分の物で埋めます |

```
元の物 X ──(1 見る・2 売れている理由を書いて分ける・3 ①と②に分ける・4 ②を自分の素材で埋める)──▶ 自分の型（スキル）
自分の型 ──(6 1本作る)──▶ 自分の物 X' ──(7 X と並べて比べる)──▶ ずれは型を直す
```

## 使う人の操作は4つだけ

1. 元の物を渡す（本文を貼る・画像やスクショを上げる・URL・動画のファイル）
2. 何を作るかを1つ選ぶ（X投稿・SEO記事・インスタ画像・ショート動画・YouTube・LP・スライド・VSL・アプリの画面・そのほか）
3. 自分の素材についての質問に、1回だけ答える
4. できた物を見て「この型で保存」を選ぶ

この4つ以外の作業（見る・分ける・測る・埋める・型にする・比べる）は Claude が進めます。使う人に途中で何度も聞かないでください。

## 守ること（最上位）

1. **写すのは売れている理由・構造・中身・情報量。写さないのは寸法と言い回し。** 部品ごとに①写す物と②一次情報を必ず分けます。①を薄めると、形だけ似て売れません。②や言い回しを写すと盗用になり、自分の物にもなりません
2. **②は作り話で埋めない。** 先に素材棚（下の「素材棚」）を探し、無い欄だけを1回の質問にまとめて聞きます。実績・数字・お客様の声・体験を作りません
3. **元の物を全部見てから分ける。** 文章は全文、LP は上から下まで、画像は要素ごと、動画は全部の場面を見ます。見ていない所は「未確認」と書きます
4. **①は理由と順番と数で書く。** 「〜な感じ」「雰囲気」「テイスト」だけで書きません。部品ごとに売れている理由を1行、構造は順番、中身は論点の箇条、情報量は数で書きます。寸法（文字の px・余白・字の大きさ・1文の字数）は①に書きません。測る台本は、構造と情報量を見るためと、元と同じ言い回しを見つけるために使います
5. **写しすぎを止める。** 作った後に必ず `references/judge.md` の「写しすぎ」「写せていない」を判定し、表現が似すぎたら出しません（下の Step 7）
6. **人の物を勝手に取りに行かない。** ログインの要るページを裏から取らない。他人の YouTube の動画を落とさない。X の投稿は使う人が本文を貼るかスクショを渡す
7. **人の顔・ロゴ・商標を写さない。** 実在の人に見える画像を作らない。画像のモデルの安全判定で止められた物を、言い換えて通さない
8. **鍵を扱わない。** 使う人の API キーやトークンを読み上げない・ファイルに書き出さない・チャットに出さない。THE・COPY は外に何も送りません

## 素材棚（使う人の②の置き場所）

作業フォルダで使っている時（Claude Code・デスクトップアプリの Code タブ）は、次を探します。

| 場所 | 中身 |
|---|---|
| `素材棚/わたし.md` | ブランド名（英小文字の短い名前）、自分が誰か、読み手、商品と価格、実績（言ってよい数字と根拠）、書き方の癖、見た目の決まり（色・書体）、使わない言葉 |
| `素材棚/自分の素材/` | 実績のスクショ、写真、過去の投稿で「良い」と決めた物、撮った動画 |
| `素材棚/元の物/` | 写したい他人の物（本文・画像・動画・URL の一覧） |
| `できた物/` | 作った物の置き場所 |

チャット（claude.ai のウェブ・デスクトップのチャット）で使っている時はフォルダがありません。`わたし.md` の欄を1回の質問で聞き、答えをこの会話の②として使います。続けて使う人には、答えを `わたし.md` の形にまとめて渡し、プロジェクトの知識に入れておくよう1行で伝えます。

`素材棚/わたし.md` が無いか空の欄がある時は、Step 4 の質問に入れます。

## 流れ

分解表の書き方は `references/sheet.md`、用途ごとの見る単位・部品の雛形・①の測り方・②の欄は `references/uses.md` にあります。媒体ごとの手順は、文章が copy-text、画像と画面が copy-image、動画が copy-video のスキルです。作業フォルダでは、Step 0 で盤を置いてサーバーを裏で立て（`--init --serve 8765`）、**Step 1〜7 のそれぞれを始める時に、その段の番号で盤を1回ずつ書きます**（`--stage <段>`）。段を飛ばしてまとめて書きません。使う人は盤で、今どこを作っているかを見ています（`references/board.md`）。

### Step 0: 元の物と、作る物を決める（コピー盤 0）

- 使う人が渡した物を元にします。何を作るか（用途）を1つに決めます。決まっていなければ、`references/uses.md` の9つから1つ選んでもらいます（質問はこの1つだけ）
- 元の物を渡されていない時は、使う人の読み手と目的が同じで、今伸びている公開の物を3つ挙げて1つ選んでもらいます。自分の過去の物は、使う人が「良い」と決めた物だけを元にします
- 同じ用途の型（`<ブランド>-<用途>-<型>` のスキル）が作業フォルダの `.claude/skills/` にあれば、新しく作らずにその型を使って Step 6 から始めます
- 作る型の名前を決めます: `<ブランド>-<用途>-<型>`。3段とも英小文字と数字（例: `mybrand-xpost-howto`、`mybrand-lp-consult`、`mybrand-short-tips`）。用途の短い名前は `references/uses.md` の表にあります

### Step 1: 元の物を漏れなく見る（コピー盤 1）

媒体ごとの単位で全部を見て、分解表（`references/sheet.md`）の「見た記録」に書きます。

| 媒体 | 見る単位 | スキル |
|---|---|---|
| 文章 | 全文を1文ずつ | copy-text |
| LP・スライド・アプリの画面・文字の画像 | 区画ごと。スマホ 390px とパソコン 1440px | copy-image |
| 写真・イラスト | 構図・人物・小物・背景・色・文字の要素ごと | copy-image |
| 動画 | カットの変わり目ごとの1枚と、音声の全文 | copy-video |

### Step 2: 売れている理由を書き、部品に分け、t2t・i2i・v2v を1つずつ割り当てる（コピー盤 2）

- 最初に、元の物全体が売れている理由を1行で書きます（誰の・どの欲求を・何で動かしているか）
- 部品に分けたら、**部品ごとに、その部品が売れている理由を1行で書きます**（例: 「読み手が自分の失敗の場面を思い出して指が止まる」「比べて見せるので、違いが1秒で分かる」）。理由を書けない部品は、見落としか飾りです。見落としなら Step 1 に戻って見直し、飾りなら部品から外します
- 部品1つが「t2t・i2i・v2v のどれか1回で作れる」大きさになるまで分けます。2つ以上の変換が混じる部品は分け直します
  - **t2t**（文章 → 文章）: 本文・見出し・コピー・台本・字幕
  - **i2i**（画像 → 画像）: 画面の配置・サムネ・図解・写真の層
  - **v2v**（動画 → 動画）: カット割り・テロップ・テンポ・BGM
- 作る順番を決めます（例: 台本 t2t → 撮影 → テロップ v2v → サムネ i2i）。この順番がそのまま型の手順になります

### Step 3: 部品ごとに①写す物と②一次情報を分ける（コピー盤 3）

| | ①写す物（理由・構造・中身・情報量） | 写さない物（寸法・言い回し） | ②一次情報（自分の物で埋める） |
|---|---|---|---|
| 文章 | 冒頭で止める仕掛けの種類、話の順番（問題 → 原因 → 反転 → 解決 → 行動 など）、扱っている話題と論点、箇条・手順・事例の数、CTA の位置とその前の押し | 1文の字数・1行の字数、元の言い回しと決め台詞 | 主張の元になる体験・事例・数字・商品 |
| 画像・画面 | 区画の順と各区画の役割、見せ方（比べて見せる・実物を先に見せる など）、1区画・1枚に載せる情報の数、構図と主役、色の役（地・本文・強調） | 文字の px・余白・行間・列の幅、元の画像・ロゴ・イラスト・文言 | 自分の写真・キャラクター・実績の画像・商品・自分の文章 |
| 動画 | 冒頭で見せる物と言うこと、元の動画が話したことの箇条、話の順番、見せ方（1場面で言うことの数・場面の種類の順）、手順・事例の数 | テロップの大きさと位置、カットの秒数の値、元の言い回しと決め台詞、元の映像と BGM | 撮る物・話す人・自分の体験と手順 |

- ①は、部品ごとの売れている理由と、順番・論点・数で書きます。②は `②-1 判断が変わった出来事` のように番号と名前を付けた「埋める欄」にします
- 動画の台本は、元の動画が話したことを箇条書きにしてから、その箇条の順と数に合わせて、自分の体験と手順で書きます
- 新しい型を作る時は、①の書き出しが終わった所で「写す所はこれで合っていますか」と1回だけ聞きます（はい・いいえで答えられる形）。同じ型を使うだけの時は聞きません

### Step 4: ②を自分の素材で埋める（コピー盤 4）

- 欄ごとに素材棚を探し、見つかった物を「データ」か「取り方」として書きます
- 見つからなかった欄だけを、**1回の質問**にまとめて聞きます。答えがそのまま欄に入る形で聞きます（「最近の出来事を教えて」ではなく「今週、判断を変えた出来事を1つ。何があって、何をやめましたか」）
- 答えてもらえなかった欄は、作り話で埋めずに、その部品を外すか「（ここに〇〇を入れる）」と残して渡します

### Step 5: 型として残す（コピー盤 5）

- `references/recipe-template.md` の形で、型のスキル（`<ブランド>-<用途>-<型>/SKILL.md`）を書きます。元の物・部品表と部品ごとの売れている理由・①写す物・②の欄と在りか・作る手順・確かめ方が全部入ります
- 文章の型には、元の文の原文（使う人が渡した物）を `references/source/` に入れておきます。作る時に原文と照らすためです。この原文は使う人の手元だけに置き、配りません
- `python3 scripts/check_recipe.py <型のSKILL.md>` が「○」で終わるまで直します。Python が無い時は、`references/recipe-template.md` の点検表を Claude が1行ずつ確かめます
- 置き場所: 作業フォルダなら `.claude/skills/<名前>/`。チャットなら、その型をフォルダごと zip にして渡し（zip の一番上を `<名前>/` にする。中身だけを zip にするとスキルとして認められない）、「設定 > スキル（Customize > Skills）からアップロードすると次から使えます」と1行で伝えます

### Step 6: 型で1本作る（コピー盤 6）

- 型の手順どおりに1本作ります（この入口の手順で直接作りません）
- 寸法は元から取りません。`素材棚/わたし.md` の「見た目の決まり」があればそれで、無ければ読みやすさの既定（各スキルの Step 6）で決めます
- 文章は copy-text、画像と画面は copy-image、動画は copy-video のやり方で作ります
- できた物は `できた物/<日付>-<名前>/` に置きます（チャットではファイルで渡します）

### Step 7: 元と並べて比べる（コピー盤 7）

- 元の物と部品ごとに並べ、部品ごとの売れている理由が、作った物でも同じ働きをしているかを見ます。そのうえで `references/judge.md` で次の2つを判定します
  - **写しすぎ**（6項目のうち2つ以上で出さない）: 固有の言い回しがほぼ同じ／段落の順と文意が同じ／構図だけでなく衣装・小物・背景まで同じ／実績の数字や事例が同じ／CTA の文言まで同じ／読み手が元を思い出せる
  - **写せていない**（6項目のうち2つ以上で型を直す）: 冒頭の強さが消えた／読み手の欲求が変わった／区画の順や寸法だけ似て、売れている理由（証拠・反論への答え・押し）が入っていない／画像の種類だけ似て画角・距離・主役が違う／口調だけ寄せて CTA の前の押しが無い／元の勝ち筋を説明できない
- 文章は `../copy-text/scripts/text_stats.py --compare` で、元と同じ8文字以上の並びを数えます（無ければ目で探します）
- **写しすぎが2つ以上なら、作った物を出しません。** ②を入れ直し、元と同じ言い回しを消してから作り直します
- 写せていない時は、作った物を手で直す前に型（売れている理由・①・手順・②の取り方）を直し、もう1本作ります。2本目で揃えば型の完成です
- 最後に、作った物と判定の結果（部品ごとに 合った・ずれた・直した）と、型の置き場所を渡します。「この型で保存しますか」とはい・いいえで聞きます

## コピー盤（コピー中の様子を見せる画面）

段が進むたびに、今の段と部品をコピー盤に出します。やり方は `references/board.md` です。

- 作業フォルダ（Claude Code・Code タブ）: 最初の1回だけ `--init --serve 8765` を裏で動かして開き、Step 1〜7 を始めるたびに `python3 scripts/board.py --dir .the-copy/board --stage <段> --job <job の JSON>` で書きます。最後に 7 を書いた後もサーバーは止めません（15分で自分で止まります）
- チャット: 段ごとに出し直すと使う人の枠を使いすぎるので、**Step 2 の後と Step 7 の後の2回だけ**出します。`python3 scripts/board.py --inline` で1枚の HTML を作り、HTML の Artifact（またはファイル）として出します
- 端末で「動きを減らす」設定の人には、動きが止まった画面で出ます

## 法律と規約（出す前に1回見る）

`references/judge.md` の「出す前の確かめ」を見ます。要点は次のとおりです。

- 著作権: 作風・構成・扱う話題はアイデアで、写してよい範囲です。元の文章・画像・ロゴ・イラストをそのまま使うと侵害になり得ます。画像を入力して作る i2i は、元に「依拠」したと見られやすいので、表現が似ていないかを特に見ます（文化庁「AIと著作権に関する考え方について」2024年3月）
- 景品表示法: 「No.1」「必ず」「誰でも」などの言い切り、根拠の無い数字、お客様の声の作り話を入れません
- 肖像権・パブリシティ権: 実在の人の顔や名前を使いません
- 各サービスの規約: 自動での取得や投稿が禁じられているサービスでは、使う人が手で貼り・手で出します

## 使わない時

- 自分の物を言い換えるだけ・誤字を直すだけ（元の物がいりません）
- 他人の物をそのまま転載したい時（THE・COPY はその手伝いをしません）
