# 型（スキル）の書式

Step 5 で書く `SKILL.md` の形です。見出しの名前は変えません（`scripts/check_recipe.py` が見出しで点検します）。

````markdown
---
name: <ブランド>-<用途>-<型>
description: |
  <ブランド>の<用途>（<型>）を、<元の物>の作り方で作る。
  使う時: 「<ブランド>の<用途>を作って」「<元の物>みたいに」等。
---

# <型の名前>

<何を・誰に向けて・どの質で作るかを1〜2行>

## 元にしたコンテンツ

- 元の物: <URL・保存先>（原文・画像は `references/source/` に保存。配らない）
- 見た記録: `references/decomposition.md` の「見た記録」
- 型にした日: <YYYY-MM-DD>

## 部品と工程

| ID | 部品 | 変換 | 道具 | 作る順番 |
|---|---|---|---|---|
| P1 | ... | t2t | ... | 1 |

## ①写す形式

部品ごとに、測った値で書きます。作る時はこの値と `references/source/` の原文を両方見ます。

- P1: ...

## ②一次情報

| 欄 | 中身 | 種類 | 在りか |
|---|---|---|---|
| ②-1 ... | ... | データ / 取り方 | <ファイルの場所・探す言葉・無い時に何を聞くか> |

## 作る手順

1. ②の欄を在りかから全部集める。空の欄が残ったら作り始めない
2. 部品表の順番で、部品ごとに①の値を守って作る
3. ...

## 確かめ方

- 元の物と部品ごとに並べ、①の値が守れているかを数える
- ②の欄が全部自分の素材で埋まっているか。元の物の事例・数字・言い回しが残っていないか
- 写しすぎ・写せていないを判定する（THE・COPY の judge.md）
- ずれた時は、作った物ではなくこの型の①・手順・在りかを直す

## 直した記録

- <YYYY-MM-DD>: <何がずれて、どこを直したか>
````

## 置き場所

- `.claude/skills/<名前>/SKILL.md`
- `references/decomposition.md`（分解表をそのまま）
- `references/source/`（元の物の原文・画像・場面の切り出し。使う人の手元だけに置き、配らない）
- `references/` に②のデータ（短く変わらない物だけ）

## Python が無い時の点検表（Claude が1行ずつ確かめる）

- [ ] 名前が `<英小文字>-<英小文字>-<英小文字>` の3段で、フォルダ名と同じ
- [ ] 見出し6つ（元にしたコンテンツ・部品と工程・①写す形式・②一次情報・作る手順・確かめ方）があり、中身が空でない
- [ ] 部品表の「変換」が全部 t2t・i2i・v2v のどれか1つ
- [ ] ①に部品の ID が全部出てくる。「な感じ」「雰囲気で」「テイストで」が無い
- [ ] ②の全部の行に在りかがあり、「種類」がデータか取り方。在りかが「聞く」だけの行が無い
- [ ] `references/source/` に元の物がある
