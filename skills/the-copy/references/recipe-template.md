# 型（スキル）の書式

Step 5 で書く `SKILL.md` の形です。見出しの名前は変えません（`scripts/check_recipe.py` が見出しで点検します）。

````markdown
---
name: <ブランド>-<用途>-<型>
description: |
  <ブランド>の<用途>（<型>）を、<お手本>が売れている理由と構造で作る。
  使う時: 「<ブランド>の<用途>を作って」「<お手本>みたいに」等。
---

# <型の名前>

<何を・誰に向けて・どの質で作るかを1〜2行>

お手本が売れている理由: <1行。誰の・どの欲求を・何で動かしているか>

## 元にしたコンテンツ

- お手本: <URL・保存先>（原文・画像は `references/source/` に保存。配らない）
- 見た記録: `references/decomposition.md` の「見た記録」
- 型にした日: <YYYY-MM-DD>

## パーツと工程

| ID | パーツ | 売れている理由 | 変換 | ツール | 作る順番 |
|---|---|---|---|---|---|
| P1 | ... | <このパーツで読み手が何をするか（止まる・分かる・信じる・試す・申し込む）を1行> | t2t | ... | 1 |

## ①真似するもの

パーツごとに、構造（順番・見せ方）・中身（話題と論点）・情報量（項目・事例・手順の数）で書きます。寸法（文字の px・余白・字の大きさ・1文の字数）と元の言い回しは書きません。作る時は、この①とパーツ表の売れている理由を見ます。

- P1: ...

## ②一次情報

| 欄 | 中身 | 種類 | 在りか |
|---|---|---|---|
| ②-1 ... | ... | データ / 取り方 | <ファイルの場所・探す言葉・無い時に何を聞くか> |

## 作る手順

1. ②の欄を在りかから全部集める。空の欄が残ったら作り始めない
2. パーツ表の順番で、パーツごとに売れている理由が働くように、①の順番・論点・数を守って作る
3. 寸法は `素材/わたし.md` の「見た目の決まり」か読みやすさの既定で決める。文の長さと語尾は自分の書き方の癖で書く
4. ...

## 確かめ方

- お手本とパーツごとに並べ、売れている理由が作ったものでも同じ働きをしているか、①の順番・論点・数が守れているかを見る
- ②の欄が全部自分の素材で埋まっているか。お手本の事例・数字・言い回しが残っていないか
- 真似しすぎ・真似できていないを判定する（THE・COPY の judge.md）
- ずれた時は、作ったものではなくこの型の売れている理由・①・手順・在りかを直す

## 直した記録

- <YYYY-MM-DD>: <何がずれて、どこを直したか>
````

## 置き場所

- `.claude/skills/<名前>/SKILL.md`
- `references/decomposition.md`（分解表をそのまま）
- `references/source/`（お手本の原文・画像・場面の切り出し。使う人の手元だけに置き、配らない）
- `references/` に②のデータ（短く変わらないものだけ）

## Python が無い時の点検表（Claude が1行ずつ確かめる）

- [ ] 名前が `<英小文字>-<英小文字>-<英小文字>` の3つで、フォルダ名と同じ
- [ ] 見出し6つ（元にしたコンテンツ・パーツと工程・①真似するもの・②一次情報・作る手順・確かめ方）があり、中身が空でない
- [ ] パーツ表の「変換」が全部 t2t・i2i・v2v のどれか1つ
- [ ] パーツ表の「売れている理由」が全部の行で埋まっている
- [ ] ①にパーツの ID が全部出てくる。「な感じ」「雰囲気で」「テイストで」が無い
- [ ] ①に寸法（px・余白・行間・字間・字の大きさ・1文の字数・1行の字数）を真似する指示が無い
- [ ] ②の全部の行に在りかがあり、「種類」がデータか取り方。在りかが「聞く」だけの行が無い
- [ ] `references/source/` にお手本がある
